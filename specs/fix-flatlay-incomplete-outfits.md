# Plan: Fix Flat-Lay Incomplete Outfit Rendering

## Task Description
Flat-lay images generated by the occasion-flat-lay pipeline frequently render incomplete outfits — showing only 1-3 garments instead of the full 3-5 item outfit. The root cause is that the image prompt sent to Gemini 2.5 Flash Image lacks **spatial layout guidance**, causing the model to merge, overlap, or drop items entirely. Accessories (bags, jewelry, shoes) are most commonly dropped. Additionally, some generated images contain text/brand watermarks (e.g., "AW24 Alaia") despite anti-text instructions.

## Objective
Ensure every flat-lay image generated by `occasion-flat-lay-service.ts` and `looks-images/route.ts` renders **ALL curated items** (3-5 pieces) with proper spatial arrangement, correct proportional sizing, and zero text artifacts.

## Problem Statement
Evidence from recent generated images:
- `outfit-1770875707400.png`: Only 2 items (white shirt + olive pants) — shoes, bag, accessories missing
- `outfit-1770876692488.png`: 3 items but has "AW24 Alaia" text watermark — items missing + text pollution
- `outfit-1770876692957.png`: 3 items (blazer, dress, heels) — bag/accessories omitted

The current `buildImagePromptFromItems()` function lists items in a flat comma-separated string with count reinforcement, but provides **no spatial positioning hints**. Image generation models render items more reliably when told WHERE each item goes on the canvas.

## Solution Approach
1. **Add a spatial layout engine** (`computeFlatLayLayout()`) that assigns grid positions based on item count and category (garments = larger/center, accessories = smaller/periphery)
2. **Restructure the image prompt** to describe items with explicit spatial positions ("upper-left quadrant: blazer", "center: dress", "lower-right: heels")
3. **Add category-aware sizing hints** ("large garment", "medium accessory", "small jewelry piece")
4. **Move anti-text instructions to the beginning** of the prompt (models weight early instructions more heavily)
5. **Strengthen compositional framing** by describing the overall layout grid before individual items

## Implementation Phases

### Phase 1: Foundation — Spatial Layout Engine
Add a `computeFlatLayLayout()` function that maps item categories to canvas positions. This is a pure function with no API dependency.

Layout strategy by item count:
- **3 items**: Inverted triangle — top-center (main garment), bottom-left (shoes/bag), bottom-right (accessory/shoes)
- **4 items**: 2x2 grid — top-left (top/outerwear), top-right (bottom/dress), bottom-left (shoes), bottom-right (bag/accessory)
- **5 items**: Cross/diamond — center (main garment), top-left (outerwear/layer), top-right (accessory), bottom-left (shoes), bottom-right (bag)
- **6+ items**: 2x3 grid with largest items on top row

Category sizing:
- **Large**: Dress, Top, Bottom, Outerwear, Jacket, Blazer, Coat, Jumpsuit
- **Medium**: Shoes, Bag, Handbag, Boots, Heels, Sneakers, Sandals
- **Small**: Accessory, Jewelry, Watch, Belt, Scarf, Hat, Earrings, Necklace, Bracelet, Ring, Sunglasses

### Phase 2: Core Implementation — Prompt Restructuring
Rewrite `buildImagePromptFromItems()` to output spatially-structured prompts like:

```
Generate a professional overhead flat-lay photograph with NO text, labels, watermarks, or written words of any kind.

The image shows exactly 4 fashion items arranged on a pristine white surface as a coordinated date night outfit. The layout is a balanced 2x2 grid:

- UPPER LEFT (large): a burgundy velvet blazer, neatly folded at a slight angle
- UPPER RIGHT (large): a deep purple silk slip dress, laid flat with straps visible
- LOWER LEFT (medium): nude pointed-toe stiletto heels, angled toward center
- LOWER RIGHT (medium): a black structured clutch bag, positioned diagonally

Each item is clearly separated with generous spacing between pieces. All 4 items are fully visible with no overlap or cropping...
```

Also update `buildFlatLayPrompt()` in `image-prompts.ts` with the same spatial approach for consistency across the hybrid pipeline.

### Phase 3: Validation & Testing
- Update unit tests for `buildImagePromptFromItems` to verify spatial position strings
- Add unit tests for `computeFlatLayLayout` layout correctness
- Visual E2E validation: trigger flat-lay generation for all 3 occasion presets and screenshot the results

## Notes
- The image generation model (Gemini 2.5 Flash Image) is non-deterministic — even with perfect prompts, it may occasionally drop items. The spatial layout approach significantly reduces this but cannot guarantee 100% compliance.
- The `looks-images/route.ts` pipeline (chat-based flat-lays) calls `buildImagePromptFromItems` directly, so the fix automatically propagates to chat flat-lays without any route changes.
- The hybrid flat-lay pipeline (`hybrid-flat-lay-service.ts`) uses `buildFlatLayPrompt` from `image-prompts.ts`, which is why that function also needs updating.
- Category classification should be case-insensitive and handle both singular/plural forms.
